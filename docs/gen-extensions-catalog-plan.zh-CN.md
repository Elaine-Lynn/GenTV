# Gen 扩展生态与目录：命名、推荐与展示设计

日期：2026-11-23。状态：设计建议，待产品选定；不是已发布功能。“Gen扩展”为本稿推荐名称，不代表用户已经确认命名。不修改应用 ID、旧 Module Card 标识或 GHCP 版本。

关联：[开放桌面内容计划](home-content-plan.zh-CN.md)、[默认呈现契约](reference/home-content-presentation.zh-CN.md)。目录是新的发现/分发能力，不混入 GHCP 本地快照 IPC，也不替代现有用户授权。

## 1. 命名建议

| 候选 | 适合的定位 | 取舍 |
|---|---|---|
| Gen扩展（推荐） | 覆盖桌面内容、应用入口及未来玩法的生态总称 | 范围充分；需配一句用户能理解的说明 |
| Gen插件（用户原提名） | 开发者与熟悉软件扩展的用户 | 熟悉、直白，但容易误以为宿主内执行的代码或非独立 APK |
| Gen小组件 | 聚焦天气、信息和状态展示 | 易懂，但会限制对影视入口与更多玩法的理解 |
| Gen卡片 | 协议输出内容的视觉单元 | 适合叫内容块，不适合当所有独立 App 的总称 |
| Gen灵感 | 编辑推荐栏目 | 有温度，但单独使用无法说明是什么 |

推荐层级：生态“Gen扩展”；用户入口“发现扩展”；目录全称“Gen扩展中心”；已安装管理“我的扩展”；编辑栏目“本周灵感”；技术名保留 GHCP，中文称“GenTV 桌面开放协议”。统一副文案：“给电视桌面，添一点新意。”

无论选择哪个品牌名，详情和开发文档必须说清：首期扩展是支持协议的独立 Android App，使用自己的包名、签名和发布来源；不是向 Launcher 动态加载第三方代码。

## 2. 面向用户的推荐策略

发现入口可从顶部应用库/更多菜单进入，首页不自动新增永久第一行图标。新功能首次提供可关闭的一次提示；用户主动访问后才加载在线目录。不挤占正常桌面内容区作广告，不强制更新、不自动置顶新应用。

首屏围绕“能给桌面带来什么”：

1. 一个精选主作品，以安装后的桌面预览为主，最多配两个次要作品。
2. 分类：影音、生活、信息、趣味；首期作品少时合并，避免空分类。
3. GenTV 出品：官方参考案例，帮助第一次体验。
4. 社区精选：说明推荐理由，例如“支持离线”“不需要登录”“适合低内存设备”；必须有依据。
5. 我的扩展：已安装、待配置、有更新、暂停维护；推荐页与管理页分开。

推荐采用可解释的编辑精选和类别浏览，优先过滤当前设备/协议不兼容项。暂不以下载量、刷票评分或付费排名驱动。可以提供“最近更新”，但更新时间不等于质量。收藏可先本地保存，不强制用户注册账号。

默认不读取观看历史、桌面布局或安装列表上传用于推荐。设备兼容匹配优先本地完成。用户已安装的 App 如已支持协议，可在本地提示启用，而不是要求重新安装。

官网是完整目录与分享入口；电视是少而精的浏览与当前设备操作入口；手机伴侣可在后续接入安装协助。三者共用作品 ID、版本记录和目录元数据，不维护互相矛盾的名单。

## 3. 电视端展示

### 发现页

电视不照搬手机商店的密集图标墙。左侧主预览 + 右侧两个精选卡，后续分类页使用宽幅截图横排。第一屏标题“让桌面，多一点可能”，短说明“天气、相册、继续观看，选你喜欢的。”

卡片必须包含：

- 在默认桌面背景上的实际效果截图；有可选背景时同时提供无背景预览。
- 作品名、作者、来源标签和一句具体价值说明。
- 当前设备操作状态：查看详情、已安装、需升级 GenTV、不兼容等。

来源标签“GenTV 出品/社区作品”和检查状态分开。不得用同一个“官方/认证”角标混淆作者身份、兼容检查和安全审计。正式名称规则应同步现有防冒充约束。

### 详情页

左侧约三分之一为作品及操作，右侧约三分之二为桌面预览。遥控器初始焦点在主要操作上，无自动播放。

- 名称、作者、简介、免费/付费/需外部订阅的实际成本；GenTV 免费不代表第三方服务一定免费。
- 主要按钮随状态变换：安装到电视 / 打开应用 / 添加到第一行 / 配置 / 更新 / 不兼容。
- 安装前可见：安装来源、兼容条件、是否联网/登录、敏感权限、许可和维护状态。
- 可展开：具体版本、SHA-256、签名指纹、更新内容、最近检查日期/范围、隐私与项目链接、举报。
- 引导：安装应用 → 配置/登录（如需要）→ 添加第一行 → 允许桌面内容 → 返回体验。
- 保留添加图标与内容展示的独立授权。添加前检查第一行可用位置，由用户选择移动/替换，不静默覆盖。

目录截图是展示层，不允许其中的按钮直接执行第三方动作；远程素材要受尺寸与数量限制，失败提供文本回退。

## 4. 官网与手机

官网用轻底色、截图优先的目录布局；提供类别、关键词及兼容条件筛选。每个条目进入稳定作品详情 URL（具体路由待实现），支持分享而不将临时下载 URL 当作品身份。

开发者入口独立且易见：“阅读开放协议”“从官方示例开始”“提交作品”。用户浏览不强制学习 API。手机端可以沿用同样的作品详情，并在设备已授权连接时显示“安装到这台电视”；没有可用连接时展示连接引导，不伪造一键安装成功。

二维码是作品详情的辅助入口，不能成为唯一安装路径；电视仍有可操作的本机安装/查看来源入口。效果图不提供假装可扫的二维码。

## 5. 官方案例建议

先交付三个能直接使用、又可学习源码的案例；第四个作为后续：

| 案例 | 用户价值 | 协议示范 | 数据条件 |
|---|---|---|---|
| Gen天气 | 聚焦就看到温度与提示 | summary、无背景默认、刷新和过期 | 手动选城市；天气数据来源与使用条件需确定 |
| 每日一图 | 桌面看一张值得停留的照片 | feature、可选背景、渐隐渐显 | 采用有权分发的素材；可用本地授权图片 |
| 接着看 | 从自己的媒体库继续 | media_row、进度、动作深链、私人授权 | 仅提供方已授权数据，不承诺读取任意 App 播放历史 |
| 家庭日历（后续） | 看下一件家庭安排 | 时间列表及个人内容失效 | 需新增模板能力时先版本化；不硬塞进首期 |

官方案例至少有一个完全离线可工作的示范路径，以及图片失败、空数据、撤权示例。网络型 App 不能仅因是“官方示例”就默认开通数据服务。首期技术计划中的媒体/天气两类参考提供方仍是必需项，生态案例不替代验证任务。

## 6. 开放、收录与推荐是三件事

- 协议开放：不收录也可自行开发、发布、安装和使用；目录不成为本地协议的许可服务器。
- 开放投稿：开发者通过公开仓库 PR/投稿入口提交；用户可提名作品，提名不等于授权分发 APK。
- 目录收录：核实身份、安装源、元数据、权限说明与协议兼容，符合规则才可安装分发。
- 编辑推荐：从已收录作品中选择，写明理由。不会自动把所有搜索到的 APK 或未审核作品推给用户。
- 闭源作品是否接收需明确规则。建议官方案例开源；社区展示开源状态，不把“使用开放协议”写成“应用必然开源”。

平台只能整理收到/发现并确认的作品，不能声称已穷尽所有基于协议开发的 App。设置“提交/补充作品”入口持续完善。

## 7. 目录最小元数据与分发

作品记录：稳定 ID、名称、作者及可验证项目关联、真实 package/component、描述、类别、截图/短演示、许可、源码/项目/隐私/反馈链接、维护状态、来源/收录/推荐状态（分字段）。

版本记录：versionCode/versionName、GHCP 主版本/能力、最低 Android/GenTV 条件、ABI 条件（如有）、下载来源与大小、APK SHA-256、签名证书指纹、权限及变化、联网/登录/成本、检查日期/范围和已测设备。不要使用截图里未经测试的“已验证”声明。

安装由 Android 系统确认，不要求 root、不承诺静默安装。电视端“安装到电视”要在安装器、来源安装许可和下载校验能力实现后上线；若暂不支持，只显示真实可用的下载/手机协助路径。官方目录暂存或镜像 APK 需先得到发布者分发许可。

每次安装必须绑定具体版本与哈希，下载后校验包、版本、哈希及签名；HTTPS 本身不是完整性检查。更新延续原作者签名；不因更新失败卸载或清数据。权限扩大需重新审阅，未经用户同意不自动更新。用户可以拒绝更新、停用或卸载。

目录更新最好使用签名清单并保留上一份有效数据；离线显示缓存与更新时间，不能将过期下载描述成最新。无 API 配置或用户未启用在线目录时不联系服务；地址通过构建配置，不能硬编码进 Launcher。目录不可用不影响已安装扩展本地运行。

撤回机制：记录具体作品/版本及原因，停止推荐或新安装；已安装项给出可理解的状态，用户选择下一步。不要把目录下架等同于平台远程卸载或绕过系统停用权限。

## 8. 建议交付顺序与检查

- [ ] E01 产品确认最终命名和用户入口，定稿后同步全部文案。
- [ ] E02 公开 GHCP 规范、可选 SDK、媒体/天气示例和兼容测试工具。
- [ ] E03 上线静态作品目录、详情、投稿规则；先收录少量完整作品。
- [ ] E04 规范化版本、哈希、签名、权限、截图和检查范围元数据。
- [ ] E05 实现电视发现/详情与真实安装状态，完成系统确认及失败回退。
- [ ] E06 实现安装后的配置、第一行位置选择和内容展示授权。
- [ ] E07 接入手机协助与本地已安装管理，身份/版本一致。
- [ ] E08 实现投稿更新、维护状态、举报和撤回流程；有证据后再编辑推荐。

验收：不兼容不误导安装；伪包/哈希/签名变化拒绝；同包重复投稿正确归并；已安装无需重复下载；安装取消/拒绝/失败可恢复；无首页位置不覆盖用户；第三方作者不被误标官方；离线及服务失败不影响 Home；来源协议规范不依赖目录在线可用。
