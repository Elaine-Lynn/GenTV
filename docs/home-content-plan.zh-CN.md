# GenTV 开放桌面内容：产品与实施计划

- 状态：GHCP 1 本地源码开发预览已接入；实现范围与测试证据见下文。不是已公开发布或实机验收结论。
- 日期：2026-11-23。
- 基线：当前工作区 Launcher `3.7.12 / versionCode 34`；HEAD `b9477b1`，工作区存在未提交的迭代。本计划针对实际工作区，不证明线上 APK 与之相同。
- 工作名称：GenTV Home Content Protocol（GHCP），对用户称“桌面内容”。名称、接口标识和线级协议在技术验证后冻结。
- 本计划中的“必须”是后续实施要求；性能数字是待验证预算，不是实测结果。

## 1. 目标、原则与范围

用户把支持协议的 App 放入第一行后，焦点停留在图标上，桌面可用空白区域显示该 App 提供的内容；用户可进入内容区，选择内容并直达 App 内对应页面。

App 决定提供什么内容，GenTV 决定展示方式、授权、焦点、资源预算和生命周期。普通图标的 OK 启动行为必须保留。内容提供方异常不得阻塞 Home。

默认呈现已确定：不带大图背景，内容块悬浮于用户当前桌面背景；切换时内容块轻移并淡化。App 可独立提供可选背景，异步准备后柔和渐显，切出时渐隐，不能阻塞内容。所有模板由宿主默认执行，无需 App 声明动画。详见[默认呈现与切换效果契约](reference/home-content-presentation.zh-CN.md)，它优先于历史效果图对背景和动效的表达。

### 首期范围

- 普通桌面模式，用户实际放入第一行的真实应用启动组件。
- 三种原生模板：横向内容卡片、信息摘要、单张主视觉。
- 默认悬浮内容轻移切换；可选背景异步交叉淡化，含快速打断、回退及减少动效。
- 每应用授权、快照校验与缓存、明确的内容深链、失败回退。
- 媒体“继续观看”和天气摘要两个参考 App，覆盖集合内容和信息内容。
- 公开规范、可选 SDK、示例、兼容性测试工具。

### 后续评估，首期不实现

- 任意第三方 View、Activity 嵌入、WebView/JavaScript、任意布局 DSL。
- 自动音视频播放、后台常驻刷新、跨应用推广、广告位。
- 家庭设备的直接写操作、支付、删除等有副作用的动作；首期动作只导航到提供方 App。
- 文件夹/HDMI 等合成图块扩展。
- Android TV Channels/Watch Next 兼容层、跨设备内容和实时数据流。

不支持协议的 App 保持原体验。安装或升级支持协议的 App 不自动改变用户排序。

## 3. 用户流程与设置

1. 安装支持协议的 App：只发现能力，不自动置顶或读取个人内容。
2. 添加到第一行：提供“允许展示桌面内容”选择，用户可以只添加图标。
3. 已在第一行的 App 升级支持协议：一次非阻断提示；拒绝后不反复弹出。
4. 设置中按应用查看来源、开关、授权状态、清缓存及重新授权入口；图标长按菜单可进入同一设置。
5. 移出第一行：停止会话和显示，保留可撤销的展示偏好；重新放入时仍检查身份、数据授权和当前模式。
6. 关闭内容或撤权：立即清除显示与对应私人缓存。普通启动不受影响。

授权分两层：GenTV 内的展示许可，以及提供方对宿主读取数据的许可。后者由提供方验证调用方 UID/包身份等，必要时通过自己的授权页确认。GenTV 的本地开关不能替代提供方访问控制。不得把未授权响应写入缓存。

## 4. 遥控器、布局与焦点契约

| 位置/事件 | 必须行为 |
|---|---|
| 第一行左右 | 图标焦点立即移动；稳定停留后才请求/显示对应内容 |
| 图标 OK | 走既有普通启动路径，不改成打开内容区 |
| 图标 ↑ | 有可操作内容时进入内容；无可操作内容时到工具栏 |
| 内容左右 | 在有限内容项内移动，边界停留，不隐式换 App |
| 内容 OK | 校验后打开该内容的提供方页面 |
| 内容 ↓ / Back | 回到来源图标；此事件不进入屏保 |
| 内容 ↑ | 到工具栏；从工具栏 ↓ 返回来源图标 |
| 普通 App 获焦 | 清除前一 App 内容，恢复现有 hero/壁纸/氛围 |
| 离开第一行 | 收起内容；进入内容区本身不算离开所属应用会话 |
| 长按 OK | 沿用图标原有菜单/排序语义；内容区不得误触发排序 |

内容区获得焦点后，仍由原 App 会话持有，不能因图标失焦而收起。保留来源组件键，不依赖可能变化的位置索引。来源消失时回到有效图标，无图标时回到可用工具栏控件。

Back 优先级：模态菜单/排序等现有局部状态 → 内容区返回 → 既有首图标/屏保逻辑。Home、Power 等系统保留键不拦截。内容焦点刷新不自动移动；保持稳定 item ID，所选项删除时选择相邻有效项，无项则回来源图标。

布局要求：内容只占宿主计算的可用区域，支持不同列数、多行设置、RTL、大字体、长文本和减少动效。不得覆盖时间、工具栏、图标或无障碍标签。空间不足时降级为摘要或隐藏内容，不压缩现有操作目标。应用来源由宿主绘制，焦点始终清楚可辨。

首期不自动翻页、播放或出声。内容刷新不抢焦点，也不重置屏保计时；只有用户输入按现有规则重置。

## 5. 模板与数据契约草案

| 模板 | 内容 | 首期限制 |
|---|---|---|
| media_row | 继续观看、收藏、最近添加 | 最多 6 项；可带进度；按空间决定可见项数 |
| summary | 天气、状态摘要 | 一组主要信息、最多 3 个指标；可有单一导航入口 |
| feature | 相册、精选内容 | 一张图、一段说明、一个导航入口 |

共同字段草案：

- 声明：协议主/次版本、关联启动组件、显式内容服务组件、模板能力。
- 请求：请求代次、宿主支持版本/模板、语言、可用布局规格、受限会话信息。
- 快照：稳定快照 ID、模板、生成时间、有效期、隐私级别、内容项、状态，以及独立的可选背景描述（概念字段 `background`）。缺省或空值均表示无背景，不继承旧背景；内容封面不推断为背景。背景失败不使有效内容失败。
- 内容项：稳定 ID、标题、副标题、受限图片引用、可选进度、动作 ID、无障碍描述。
- 状态：有内容、空内容、需授权、需登录、暂不可用、不支持版本。空内容是有效响应，不算故障。

示例仅表达数据形态，不是可直接实现的线级接口：

```json
{
  "protocolMajor": 1,
  "snapshotId": "continue-watching-42",
  "template": "media_row",
  "ttlSeconds": 900,
  "privacy": "personal",
  "items": [{
    "id": "episode-123",
    "title": "继续观看",
    "subtitle": "第 3 集",
    "image": "content://example.provider/art/123",
    "progress": 0.42,
    "actionId": "resume-123"
  }]
}
```

版本规则：不支持的主版本保留普通启动；次版本通过能力协商扩展。未知可选字段忽略，未知必需能力拒绝。宿主验证长度、数量、类型、枚举、重复 ID、非法数值和 URI；时间计算考虑设备时钟变化，不信任应用自报时间无限保活。

线级规范冻结前必须明确：Manifest 标识、IPC 方法/线程、错误码、取消语义、序列化格式、字段确切上限、图片访问授权、动作传递与验证、权限模型、版本降级、签名轮换策略。未经冻结不得把示例字段宣称为稳定 API。

## 6. 架构与生命周期

建议职责拆分（名称可在实现时调整）：

| 模块 | 责任 |
|---|---|
| ExtensionRegistry | 应用发现、组件关联、版本能力、包变化 |
| ConsentStore | 展示决定、身份与授权范围 |
| ContentSessionController | 当前来源、请求代次、超时、取消和生命周期 |
| SnapshotRepository | 验证、过期、缓存、去重和资源预算 |
| TemplateRenderer | 原生模板、有界图片和宿主统一内容轻移/淡化；不阻塞输入 |
| BackgroundCoordinator | 可选背景异步准备、代次校验、去重、有界交叉淡化及默认壁纸恢复 |
| FocusCoordinator | 图标、内容、工具栏的显式焦点路径 |
| ActionRouter | 提供方归属校验、现有启动限制和安全失败 |

首选验证显式绑定的异步 Service；ContentProvider 为备选。P0 用冷启动、无响应、权限及资源实测决定传输方案。第三方在自身进程准备快照，宿主不执行其代码。网络由提供方管理，焦点切换不要求联网；首期宿主不直接下载应用给出的任意网络 URL。

会话状态：未启用 → 待停留 → 加载 → 展示（图标/内容持焦）→ 暂停/清除。任意加载阶段都可进入空内容、需授权、失败回退。每次来源、身份、模式或授权变化递增代次；回调必须同时匹配来源、代次和生命周期。取消只是尽力通知，迟到响应仍必须丢弃。

- 第一行稳定停留后，只连接当前提供方；不因左右浏览唤醒所有 App。
- 离开 Home、失去有效窗口、打开屏保、待机或切模式时停止会话，释放连接与资源。
- 设置、排序和模态菜单暂停交互；返回时重新确认来源和缓存有效性。
- 同一提供方的请求有界合并；超时断开并退避，不无限追加线程或任务。
- 提供方连续故障按应用熔断，本会话回退；重试条件与次数在 P0 冻结。
- 图片解码、I/O、IPC 不阻塞主线程；异常与资源耗尽预防分别设计，不能靠捕获异常保证安全。

## 7. 身份、安全、隐私与缓存

- 验证服务、启动组件、图片来源和动作属于声明的真实提供方；显式绑定，不能信任响应里自报的包名。
- 提供方独立校验宿主。私人数据默认不向任意调用者公开；参考 App 必须演示授权而非仅检查自报包名。
- 图片使用受限 content URI/文件描述符；限定大小、像素和解码内存，超限拒绝。授权最小化并随会话结束回收；不接受任意本地路径。
- 首期动作仅进入该 App。拒绝任意 Intent 解析、跨包跳转、任意 extras/权限转授；再次经过儿童和现有启动门禁。
- 不向提供方泄露其他 App 列表、桌面排序、设备标识或其他提供方内容。
- 内容标记 public/personal 等明确隐私等级；缺少有效隐私声明按保守策略拒绝或不缓存，具体规则在 P0 固定。
- 私人缓存首期仅内存保存，不进入备份、桌面 JSON 导出、日志或统计。公开磁盘缓存如需引入，另定义容量、清除与保留策略。
- 退出账号需要提供方使快照失效；协议必须定义失效通知或重新验证方式。未验证该机制前不宣称“退出即清除”。过期私人内容立即隐藏。
- 撤权、卸载、停用、身份失效时清除对应显示与缓存；重装、签名轮换和多签名规则必须显式测试，不静默继承授权。
- 不接受假系统提示、假认证、广告位、跨应用推广及未经同意的追踪。提供单应用关闭和举报；格式校验不能保证识别全部违规内容。
- 规范、SDK 和测试工具可公开，无需官方账号/服务/付费认证。许可及新增依赖归属按仓库规则处理。

## 8. 既有能力兼容矩阵

| 场景 | 首期要求 |
|---|---|
| 普通 App / Module Card spec 1 | 无行为退化，无重复图标 |
| 儿童模式/锁定 | 默认关闭第三方动态内容；直接入口不得绕过门禁 |
| 文件夹/输入源/其他合成图块 | 保留当前操作，无提供方映射猜测 |
| 排序/隐藏/远程配置改变 | 重新判断真实第一行成员；取消失效会话 |
| 多启动组件/多入口 | 按组件关联，不能仅按包合并 |
| 改名/自定义图片 | 用户图标设置保留；来源身份不能被自定义名伪装 |
| 返回 App / Home / 待机恢复 | 恢复有效来源与焦点，重新验证过期和授权 |
| 屏保 | 不自动延长计时、不播放桌面视频、不泄露残留私人内容 |
| 无网络/无 API 配置 | 本地快照可工作，不依赖官方云 |
| 桌面导出/撤销/手机编辑 | 不加入运行时快照或凭据；不改变 schema 2 现有解释 |
| 关闭功能/回滚 | 普通桌面正常启动，未知独立状态不破坏原配置 |

若后续手机需要编辑启用偏好，另立配置协议变更，处理旧客户端遗漏字段和 revision/undo，不能夹带在动态快照通道里。

## 9. 初始性能预算

| 指标 | 待验证目标 |
|---|---|
| 稳定停留 | 约 200 ms；快速划过不请求 |
| 有缓存呈现 | 触发后 100 ms 内 |
| 无缓存等待 | 约 1 秒；超时显示原桌面，不永久 loading |
| 元数据 | 单快照不超过 64 KiB；精确编码计量在规范冻结 |
| 内容项 | 每应用最多 6 项 |
| 解码图片缓存 | 全局有界，初始 12 MiB，含可选背景；旧/新背景叠加峰值也计入，按 1 GB 设备结果调整 |
| 内容动效 | 初始位移 16–24 dp、入场 280 ms、退场 180 ms，待实测调校 |
| 背景动效/加载 | 初始交叉淡化 700 ms；准备期限 2 秒，与内容等待独立 |
| 活跃提供方 | 同时最多 1 个 |
| 后台刷新 | 离开 Home 后停止宿主内容刷新 |

64 KiB 不包括将大图片塞入载荷的许可。测量宿主与提供方的冷启动、峰值内存、PSS、焦点延迟和掉帧；与关闭功能的同设备同配置基线比较。P0 必须确定可重复的采样方法、超时起点、分位数和允许回归阈值。

## 12. 产品效果与发布判断

先比较继续观看的按键数、正确内容打开率和完成时间；同时关注用户主动关闭比例、提供方失败率及焦点/内存回归。不得将桌面停留时间增长直接当成功。诊断默认本地可查；远程统计另行征得同意，不上传标题、观看记录、图片 URI 或账号信息。

发布阻断项：Home 不可操作、焦点陷阱、儿童门禁绕过、私人内容越权/失效失败、无界资源增长、原配置损坏、协议兼容承诺无证据。其他问题记录影响、回退方式和是否影响发布。

## 13. 调研依据与未决策事项

调研日期：2026-11-23。以下为官方平台机制，不代表 GHCP 已实现这些能力：

- [Apple TV Services](https://developer.apple.com/documentation/tvservices)：选中 App 时呈现 Top Shelf 内容，扩展提供内容；启发焦点驱动的体验。
- [Apple Top Shelf](https://developer.apple.com/design/human-interface-guidelines/top-shelf)：电视主屏内容区域的交互参考。
- [Android TV Channels](https://developer.android.com/training/tv/discovery/recommendations-channel)：频道、节目和用户管理模型；不证明第三方 Launcher 可在所有设备读取现有 App 数据。
- [Android Widgets](https://developer.android.com/develop/ui/views/appwidgets)：宿主与 RemoteViews 模型；不直接作为首期唯一协议。
- [TV navigation](https://developer.android.com/training/tv/get-started/navigation)：遥控器可达性与清晰返回路径。
- [Package visibility](https://developer.android.com/training/package-visibility/declaring)：Android 11+ 查询可见性处理。
- [ContentProvider permissions](https://developer.android.com/guide/topics/providers/content-provider-creating)：数据访问边界及 URI 授权参考。
- [Binder transaction limits](https://developer.android.com/reference/android/os/TransactionTooLargeException)：缓冲区共享且有界，不能将上限当可用载荷预算。

P0 必须关闭的决策：协议命名/发现声明、传输选择、宿主授权流程、签名轮换、图片授权及清理、退出账号失效机制、动作编码、TTL 上限/时钟策略、性能阈值、布局降级。每个结论记录选择、证据和影响，并同步稳定规范及测试；不得让示例或实现自行成为隐含规范。
