# Gen 插件 App 开发规范：默认呈现与切换效果

状态：产品呈现要求；三模板的默认悬浮、轻移和可选背景淡化已在本地开发预览实现，完整矩阵仍待验收。更新：2026-11-24。开发者以 [Gen 插件 App 开发规范](home-content-development.zh-CN.md)的当前实现边界接入，不把本文全部目标视为已交付能力。

本契约是[开放桌面内容计划](../home-content-plan.zh-CN.md)的默认呈现要求，适用于所有模板。App 只提供内容和可选背景资源，宿主统一执行效果；App 不必声明动画，也不能通过自定义脚本、曲线或时长覆盖效果。当前 GHCP 1 字段见开发规范；以下默认语义必须保留。

## 1. 默认无大图背景

- 不提供背景是完整、正常、推荐的接入方式，不视为缺字段或降级。
- 内容块直接悬浮于用户当前桌面背景之上，不自动添加整屏底板，不把封面、海报、专辑图或图标推断成背景。
- “默认桌面背景”指用户当前生效的壁纸/桌面背景，包括用户已启用的轮换；不能改写用户壁纸设置或换成协议指定的统一壁纸。
- 悬浮指空间和层级感，不是内容持续上下漂浮。允许轻微阴影、细边界或局部低透明度衬底保证可读性；不强制所有内容使用玻璃卡片。
- 工具栏和应用栏位置稳定。内容区不遮挡既有操作目标；仅当前实际焦点使用焦点轮廓。
- 内容封面与可选背景是两个独立角色。feature 模板的大图默认仍是内容块，不自动扩展为全屏背景。

## 2. 内容块的默认移动效果

第一行图标焦点立即响应。约 200 ms 稳定停留后提交目标内容；网络、IPC 和图片解码不得卡住遥控器响应。

| 情形 | 默认效果 |
|---|---|
| 首次显示 | 内容块从轻微下移位置抬入，同时淡入 |
| App 间左右切换 | 旧内容沿导航方向移出并淡出，新内容从反方向轻移入并淡入 |
| 同一 App 内容更新 | 保留稳定项和焦点，只对变化项做局部淡化/轻移，不重播整个入场 |
| 退出内容展示 | 内容块轻移并淡出，露出原桌面 |

建议初始参数：位移 16–24 dp；入场 280 ms，退场 180 ms；使用平滑减速曲线，无弹跳和过冲。同一组内容以整体移动为主，可有不超过 20 ms 的轻微错峰，但整组应在 360 ms 内稳定。数值是初始调校值，P0 可据实机调整并记录；“短距离、柔和、不中断输入”的语义是必须项。

向右浏览时旧内容向左退出、新内容从右进入；向左反之。按实际视觉方向确定，不用索引增减硬编码，RTL 同样成立。首次出现或没有方向信息时使用轻微上移淡入。仅动画 translation/alpha，不逐帧改变布局尺寸；不靠大幅缩放、旋转、持续漂浮或强烈模糊表达轻盈。

跨应用变更一旦提交，旧来源的动作立即失效；旧内容仅可短暂作为不可交互的退场画面，不可被辅助功能聚焦。新数据尚未就绪时退回原桌面或显示轻量局部占位，不冒充目标 App 展示旧内容，也不让整屏变成 loading。

## 3. 可选大图背景

App 可以在快照中独立提供可选背景资源。GHCP 1 字段为 `background`，值为受限图片 URI 字符串或 null。资源版本通过 URI 路径区分；当前不提供独立裁切提示或背景能力协商字段。

- 字段缺省或显式空值：本快照无背景，不继承该 App 旧快照或其他 App 的背景。首期快照按完整替换解释，不作隐含补丁。
- 资源可用：内容先展示，背景独立异步读取、采样和解码；准备好后渐显。已有缓存同样柔和出现，不硬切。
- 大图不能成为内容首帧的前置条件。不得为了等背景推迟内容块入场或重新播放内容入场。
- 背景只做 alpha 渐隐渐显；不随内容平移，不作视差、缩放或自动轮播。
- 宿主控制裁切、可读性遮罩和最终显示，不接受 App 自绘整屏 UI。遵循原协议的图片来源、权限和尺寸校验，不引入任意网络 URL 下载。
- App 背景是临时视觉覆盖层，始终位于原桌面背景上、内容/工具栏/应用栏下，不写入壁纸配置。

建议背景交叉淡化 700 ms，允许 P0 在 600–900 ms 内调校；慢于内容切换，使内容轻快到位，背景随后柔和跟随。柔和来自透明度与合成，不要求运行时全屏模糊。

## 4. 背景切换矩阵

| 当前 → 目标 | 必须行为 |
|---|---|
| 默认 → 无背景 | 原桌面背景保持，只有内容轻移切换 |
| 默认 → 有背景 | 先显示内容；新背景准备好后从透明渐显 |
| A 背景 → B 背景且 B 已准备 | A/B 直接交叉淡化，底层默认背景持续存在，不插黑帧 |
| A 背景 → B 背景尚未准备 | A 先柔和淡出至默认背景；B 完成后渐显，不因等待保留 A |
| A 背景 → 无背景/普通 App/退出 | A 柔和淡出，恢复当前默认桌面背景 |
| 目标背景失败/超限/无权限 | 保留目标内容与默认背景；不影响启动，不重试成闪烁循环 |
| 同一有效背景重复返回 | 按资源身份去重，不反复淡入；背景改变独立切换 |

若 B 在 A 淡出中完成，从当前可见透明度平滑接续到 B，不先重置为全透明或不透明。应用背景完全覆盖时可暂停底层壁纸无效解码/绘制；切出前恢复当前有效壁纸，不能短暂露出黑底或更改用户轮换偏好。

## 5. 打断、隐私与资源

- 内容和背景有独立加载进度，但共享来源组件、会话代次、快照及授权校验。A→B→C 时 A/B 迟到图片不得显示到 C；同一来源内旧快照背景也不得覆盖新快照。
- 连续输入始终以最新目标为准，取消/替换旧动画，从当前可见位置和透明度接续，不排队播放完整动画；内容、背景均不得形成无限图层或任务。
- 背景准备期限建议自目标快照接收起 2 秒；超时取消本次展示，迟到结果不再突然出现。新的明确请求可重试，不后台无限轮询。该期限独立于内容约 1 秒等待预算。
- 常态最多保留一张 App 背景；交叉淡化时最多旧/新两张。原壁纸与内容图片另计，仍受全局内存预算约束；不能把两张全分辨率 4K 背景默认解码入内存。
- 内存不足优先拒绝/降采样可选背景，保持内容与焦点流畅。瞬时故障允许淡出；撤权、私人快照过期、身份失效、儿童锁触发等需要立即遮蔽私人内容及背景，不为完成动画延长泄露时间。
- 背景继承快照的隐私和有效期，不能以装饰资源名义绕过；私人背景不写磁盘、日志、导出或统计。屏保入场截帧不得携带本应隐藏的私人内容或背景。
- 离开 Home、待机或切模式时停止动画及加载，释放覆盖层；返回后重新验证来源、授权与有效期。

## 6. 减少动效与低性能降级

- 默认执行上述效果，开发者无需逐 App 配置。
- 用户开启减少动效时取消位移、错峰及弹性，改为短淡化（建议 120 ms）；系统关闭动画时直接设置最终态，不保留计时器等待。
- 低性能降级保留正确内容、焦点和来源；依次取消错峰/额外阴影、降低背景采样，再停用可选背景。不得改用更重的模糊效果。
- 降级不改变无背景的默认语义；App 不能要求宿主必须展示大图才能使用内容。

## 7. 验收要求

以下项目并入主计划 A13–A16，均为待验收：

- 无背景与背景空值：现有壁纸不变，封面不铺满，无整屏遮挡。
- 有背景冷加载、缓存命中和失败：内容均不等背景，背景独立柔和切换。
- 完整覆盖上述切换矩阵；无黑帧、硬切、跨来源残留、重复入场。
- A→B→C 快切、方向反转、RTL、背景迟到/超时、同 App 新快照：最终来源正确，无动画积压，按键持续可响应。
- 减少动效、系统关闭动画、低内存、待机和屏保：按规则降级并释放资源，私人内容立即失效。

历史生成图只作为布局与气质参考，其中全屏大图不是协议默认；后续实现、截图和新效果图必须优先遵循本契约。静态图不能证明移动或渐隐渐显已实现，验收需真机录屏与资源/响应测量。
