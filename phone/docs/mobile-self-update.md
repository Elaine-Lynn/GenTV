# GenTV Remote 手机自更新

客户端已实现：检查版本 → 用户点击下载 → 流式下载/进度/取消/重试 → SHA-256 校验 → APK 包名、版本号、版本名称、最低 SDK 与签名证书校验 → 系统安装确认。仅修改手机 App，不修改电视 Launcher、安全保护逻辑或电视 APK。

仓库已包含服务端更新清单读取实现；历史实机验收已完成正式签名版本的应用内升级，见 [发布验收记录](release-acceptance.md)。这不代表当前线上服务已重新验证。官方发布接口为 `GET https://api.gentv.app/tv/update?platform=mobile`；源码构建默认不配置在线服务，可通过 `-PgentvApiBaseUrl` 或 `GENTV_API_BASE_URL` 配置 API 基址。此请求不附带设备标识、电视信息或用户账号。接口应返回发布渠道的最新稳定版本（即使客户端已经是最新版本也返回同一结构），不能用空响应、404 或错误页表示已是最新。

## 响应契约

HTTP 200，`Content-Type: application/json`，响应体不超过 64 KiB：

```json
{
  "version": "0.10.0",
  "version_code": 12,
  "apk_url": "https://api.gentv.app/tv/releases/gentv-remote-0.10.0.apk",
  "sha256": "替换为APK文件真实SHA256的64位十六进制字符串",
  "size_bytes": 45000000,
  "min_sdk": 26
}
```

- `version_code` 为 Android 单调递增版本号，必须与 APK 内版本号相同；与当前安装版本比较决定有无更新。`version` 必须与 APK 版本名称相同，使用纯数字 major.minor.patch（也接受一或两段）。
- `min_sdk` 必须为整数且不小于 26；手机不兼容时不提供设置页下载操作，APK 内最低 SDK 也会再次校验。
- `size_bytes` 必须与最终 APK 的实际大小相同，不超过 200 MiB。
- `sha256` 必须由正式发布流水线针对最终签名 APK 计算；示例中的占位文字不能用于真实接口。
- `apk_url` 只允许与构建配置 API 基址一致的 HTTPS 主机、端口及路径前缀。官方配置对应 api.gentv.app、默认 HTTPS 端口和 `/tv/` 下路径。拒绝用户信息、fragment、编码路径与路径回退。下载不跟随重定向，服务端应直接返回完整 APK（HTTP 200），不要重定向至 CDN。
- 客户端为旧数据保留 GitHub release JSON 解析兼容，但这种响应只允许跳转官网，不能启动内置 APK 安装流程。新服务必须使用以上完整字段。

网络错误、非 200、无效 JSON、字段缺失或不合法均显示检查失败。自动提示沿用每日缓存，失败不写入“检查成功”时间；手动检查绕过缓存与忽略版本记录。较旧缓存只能用于提示，下载和安装仍需有效完整元数据。

## 安装与发布

- APK 保存在手机私有缓存 updates/ 内。下载失败、取消或校验失败清理下载中的文件；再次下载覆盖旧文件。无后台服务、无存储权限、无静默安装。
- 下载有连接/读取超时，取消会在读取超时或下一个数据块到达后结束。下载中断后不做断点续传；Activity 旋转期间下载由 ViewModel 保留。已完成校验的 APK 与待安装元数据保存在私有缓存；进程重建时重新执行哈希、包名、版本与签名检查，合法才恢复安装入口，篡改、损坏或已经安装的版本会被清理。取消会清除待安装元数据。
- 安装前再次计算 SHA-256，并验证包名必须是当前手机应用，APK 版本号必须更高且匹配接口。证书要求与当前安装版本的当前签名证书集合完全相同，暂不支持密钥轮换。签名轮换需要独立设计与验证，不能关闭签名校验。
- 通过 FileProvider 只授予 APK 临时读取权限，使用系统安装器完成最终签名/兼容性检查。Android 8+ 用户需允许此应用安装其他应用；客户端打开授权设置，返回后再点击“安装更新”。拒绝授权或取消系统安装不视为已更新。
- 界面只显示“安装器已打开”，不会谎报安装成功。新版本被实际安装后由 Android 替换当前进程。
- 正式发布须使用相同 applicationId 和正式发布密钥。debug 签名不能安装正式签名更新，反之亦然。不要将 APK 或密钥提交到仓库。
- Play 安装版本继续使用 Play 更新，不走此自更新流程；本实现面向官网侧载渠道。若以后发布 Play 专用版本，应单独移除侧载安装权限并按商店要求打包。

系统 API 依据：[PackageManager：安装来源授权与签名信息](https://developer.android.com/reference/android/content/pm/PackageManager)。

## 验证

`./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug --offline --continue --console=plain`

测试覆盖完整元数据解析、下载来源限制、SHA-256、短包/超长包/篡改、取消清理、错误包名/版本/签名/SDK，以及设置页下载入口。每次发布仍需使用同一正式密钥签署的两版 APK，在真实手机验证：取消下载、断网、拒绝安装授权、返回继续安装、取消系统安装和真正升级。已在真实手机完成正式签名 0.9.0/code11 → 0.9.2/code13 的应用内下载安装升级；断网下载、取消下载和取消安装等异常流程仍需补充实机验收。
